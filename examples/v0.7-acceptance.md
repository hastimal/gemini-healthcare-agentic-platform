# v0.7 Acceptance Example

## Purpose

This document records one successful end-to-end acceptance run for:

```text
v0.7 — FHIR Healthcare Interoperability
```

The goal of the run was to validate the complete architecture:

```text
Google ADK
    |
    v
Search Planner Agent
    |
    v
Healthcare Research Agent
    |
    v
MCPHealthcareRetrievalOrchestrator
   /          |          \
  v           v           v
NPPES       PubMed      FHIR R4
  \           |           /
   \          |          /
    v         v         v
       SearchResult[]
            |
            v
Evidence & Answer Agent
            |
            v
Score -> Rank -> Select
            |
            v
Grounded Answer
```

This is an acceptance example only.

The values below describe one observed run and are not fixed performance guarantees or benchmark results.

---

# Flagship Query

The acceptance run used:

```text
Find three pediatric dentists in Houston for a child who is scared of
going to the dentist. Compare them using trustworthy sources, provider
credentials, services, and location, and explain why you selected each one.
```

The query was intentionally chosen because it exercises multiple evidence needs:

```text
provider discovery
location
specialty
general scientific evidence
source authority
grounding
citations
FHIR interoperability
```

---

# Expected Architectural Behavior

The query should exercise exactly three agents:

```text
1. Search Planner Agent
2. Healthcare Research Agent
3. Evidence & Answer Agent
```

FHIR must remain a tool/data-source capability rather than becoming a fourth agent.

---

# Search Planning

The Search Planner Agent produced:

```text
7 generated queries
```

The plan included provider discovery, general research, source-discovery queries, and an explicit FHIR interoperability query.

The FHIR query targeted:

```text
PractitionerRole
```

for provider-oriented healthcare interoperability.

---

# Important Planning Boundary

The planner can generate queries intended to identify sources such as:

```text
professional directories
state licensing authorities
FHIR resources
biomedical literature
```

Generating a query does not mean the source was retrieved.

Generating a query also does not mean that:

```text
credentials were verified
a license was verified
board certification was verified
services were verified
disciplinary history was checked
```

The acceptance run preserves that distinction.

# Why FHIR Was Not Selected

The public HAPI FHIR records were useful for validating interoperability.

They were not authoritative enough to support provider recommendations.

Therefore:

```text
FHIR retrieved
      |
      v
FHIR normalized
      |
      v
FHIR scored
      |
      v
FHIR observable
      |
      X
provider grounding slot
```

This demonstrates an important system distinction:

```text
retrieved evidence
      !=
selected grounding evidence
```
